# 13페이지 --- Multi-Radar Technology Comparison

> 동일한 평가축을 사용하여 3개 이상의 기술·제품·기업의 특성을 비교하는
> 레이아웃. 원본 13페이지의 핵심은 상단에 핵심 장점을 간결하게 설명하고,
> 하단에 동일 규격의 Spider/Radar Chart를 병렬 배치하여 각 대안의 특성
> 차이를 직관적으로 보여주는 것이다.

------------------------------------------------------------------------

## 0. 적용 범위

다음 콘텐츠에 우선 적용한다.

-   기술 A / B / C 비교
-   자사 / 경쟁사 비교
-   제품군 성능 비교
-   복수 솔루션의 정성·정량 특성 비교
-   5개 이상의 동일 평가항목을 기준으로 여러 대상을 비교

공통 Header, Logo, 기본 폰트, 브랜드 컬러 등은 Hard Rule을 따른다.

------------------------------------------------------------------------

## 1. Layout Identity

핵심 구조:

`Title + Key Advantage Summary + 3-Column Radar Comparison`

기본 화면 구성:

``` text
[Main Title]

① 핵심 장점
② 핵심 장점
③ 핵심 장점
④ 핵심 장점


 [Radar A]        [Radar B]        [Radar C]

 [기술 A]         [기술 B]         [기술 C]
```

상단은 설명 영역, 하단은 비교 시각화 영역으로 명확히 분리한다.

------------------------------------------------------------------------

## 2. Upper Summary Area

상단에는 비교 대상 전체를 설명하는 핵심 장점 또는 비교 기준을 배치한다.

권장: - 3\~5개 항목 - 한 항목당 1줄 우선 - 번호형 List 사용 가능 -
장문의 설명보다 비교 차트를 이해하기 위한 Context 제공에 집중

상단 설명이 지나치게 길어 하단 Chart가 축소되지 않도록 한다.

------------------------------------------------------------------------

## 3. Radar / Spider Chart 기본 규칙

Radar Chart는 동일한 평가항목을 기준으로 여러 대상의 특성 Profile을
비교할 때 사용한다.

권장 평가축: - 최소 5개 - 권장 5\~7개 - 최대 8개

예:

-   재활용 효율
-   공정시간
-   연속공정
-   에너지 효율
-   양산성
-   친환경성

각 Radar Chart는 반드시 동일한 축 순서와 동일한 Scale을 사용한다.

비교 대상별로 축 순서를 변경하지 않는다.

------------------------------------------------------------------------

## 4. Data Requirement --- Hard Rule

Radar Chart의 값은 다음 중 하나를 기반으로 한다.

1.  사용자가 제공한 정량 데이터
2.  사용자가 직접 제공한 평가 점수
3.  명확한 기준에 따라 사전에 정규화된 데이터

AI가 자사 또는 특정 기업의 우위를 표현하기 위해 임의의 점수를 생성하지
않는다.

정성 정보만 제공된 경우 임의로 1\~5점 등의 수치로 변환하지 않는다.

------------------------------------------------------------------------

## 5. Scale

모든 비교 대상은 동일 Scale을 사용한다.

예: - 1\~5점 - 1\~10점 - 0\~100점

Scale이 다른 데이터를 사용할 경우 먼저 정규화가 필요한지 판단한다.

정규화가 필요한 경우 사용자 승인 없이 의미가 다른 지표를 임의 변환하지
않는다.

------------------------------------------------------------------------

## 6. Multi-Radar Layout

기본형은 3개의 Radar Chart를 수평 병렬 배치한다.

### 기본 구조

-   Chart A: Left
-   Chart B: Center
-   Chart C: Right

각 Chart의: - 크기 - 축 개수 - 축 위치 - Grid 크기 - Label 거리

를 동일하게 유지한다.

Chart 사이에는 Vertical Divider를 사용할 수 있다. 두께·색상·기본
스타일은 이 문서에서 재정의하지 않으며, **Hard Rule §11 Vertical
Content Divider**(Solid 기본값) 스펙을 그대로 따른다.

Divider는 비교 영역을 구분하는 보조 요소이며 Chart보다 높은 시각적
Weight를 갖지 않는다.

------------------------------------------------------------------------

## 7. Comparison Target Label

각 Chart 하단에는 비교 대상명을 명확하게 표시한다.

예:

`[ 흡착제 ]`

`[ 추출제 & 분리막 ]`

`[ 전기화학 ]`

또는

`[ COSOLUS ]`

`[ Company A ]`

`[ Company B ]`

비교 대상명은 Chart 내부가 아니라 Chart 하단에 독립적으로 배치하는 것을
우선한다.

핵심 또는 자사 대상은 Brand Teal 계열로 강조할 수 있다.

------------------------------------------------------------------------

## 8. Radar Visual Style

Radar Grid는 얇고 절제된 Neutral Gray Line을 사용한다.

-   Grid Fill 사용 금지
-   과도한 축선 강조 금지
-   3D 효과 금지
-   Shadow 금지
-   Marker 남용 금지

데이터 Polygon은 단색 Fill + 적절한 Transparency를 사용한다.

Polygon 외곽선은 필요 시 동일 계열의 진한 색을 사용할 수 있다.

전체적으로 Chart 자체보다 Polygon의 Shape가 먼저 인식되도록 한다.

------------------------------------------------------------------------

## 9. Color Logic

원본처럼 비교 대상마다 서로 다른 Fill Color를 사용할 수 있다.

단, 색상 선택은 회사 공통 Palette 범위에서 이루어져야 한다.

권장 구조:

-   일반 비교 대상: Light Accent
-   핵심 비교 대상: Brand Teal
-   보조 비교 대상: Secondary Accent

자사 또는 핵심 기술을 강조해야 하는 경우 중앙 또는 시각적으로 우선되는
위치에 배치하고 Brand Color를 우선 적용할 수 있다.

임의의 Rainbow Palette는 사용하지 않는다.

------------------------------------------------------------------------

## 10. Label Rules

축 Label은 Radar 외곽에 배치한다.

-   Label이 Polygon 또는 Grid와 겹치지 않도록 한다.
-   모든 Chart에서 동일한 Label 위치를 유지한다.
-   축 Label은 한 줄을 우선한다.
-   긴 항목은 의미를 유지하면서 축약할 수 있다.

각 축의 방향과 의미는 모든 Chart에서 동일해야 한다.

------------------------------------------------------------------------

## 11. Chart Selection Interaction Rule

### A. 사용자가 Radar / Spider Chart를 명시한 경우

사용자가 다음과 같이 명시적으로 요청하면 추가 확인 없이 Radar Chart를
사용한다.

예: - "스파이더차트로 만들어줘" - "레이더차트로 비교해줘" - "6개 항목을
방사형으로 보여줘"

단, 필요한 수치가 제공되지 않은 경우에는 점수 또는 데이터를 요청한다.

------------------------------------------------------------------------

### B. 사용자가 5개 이상의 비교항목이 포함된 표를 제공한 경우

사용자가 여러 기업·제품·기술을 5개 이상의 공통 평가항목으로 비교하는
Table을 제공했으나 Chart 형식을 지정하지 않은 경우, AI는 콘텐츠를
분석하여 Radar Chart 또는 다른 Chart가 정보 전달에 더 효과적인지 판단할
수 있다.

이 경우 시각화 방식 변경이 의미 있는 수준이라면 사용자에게 다음과 같이
제안할 수 있다.

예시 질문:

> 현재 데이터는 여러 대상을 5개 이상의 동일 항목으로 비교하고 있어
> 스파이더차트로 변환하면 각 대상의 종합적인 특성 차이를 더 직관적으로
> 보여줄 수 있습니다. 기존 표를 유지할까요, 아니면 스파이더차트 또는
> 다른 비교 차트로 시각화할까요?

질문은 단순 형식 확인을 위한 것이 아니라 시각화 변경이 실제 전달력을
개선할 때만 한다.

------------------------------------------------------------------------

## 12. Chart Recommendation Logic

5개 이상의 비교항목이 있다고 해서 무조건 Radar Chart를 사용하지 않는다.

### Radar Chart 우선 검토

-   동일한 5\~8개 평가항목
-   여러 기업/제품의 종합 Profile 비교
-   각 대상의 강점/약점 Pattern이 중요
-   개별 수치의 정확한 차이보다 전체적인 Shape 비교가 중요

### Bar Chart 우선 검토

-   정확한 수치 차이가 중요
-   항목별 Ranking이 중요
-   특정 지표의 우열을 명확하게 보여줘야 함
-   항목 수가 많아 Radar Label이 복잡해짐

### Line Chart 우선 검토

-   시간 흐름
-   연도별 변화
-   공정 단계에 따른 연속적 변화

### Table 유지 우선

-   정확한 수치를 읽어야 함
-   단위가 서로 다름
-   정성 설명이 많음
-   항목별 조건 또는 주석이 중요

------------------------------------------------------------------------

## 13. Optional Conversion Question

에이전트가 표 형태의 콘텐츠를 받았을 때 다음 조건을 모두 만족하면 시각화
전환 여부를 질문할 수 있다.

1.  비교 대상이 2개 이상
2.  공통 비교항목이 5개 이상
3.  데이터가 수치형이거나 동일 Scale로 변환 가능한 형태
4.  Chart 사용 시 전달력이 명확히 개선될 가능성이 있음

질문 예시:

> 비교항목이 6개이므로 현재 표를 그대로 사용하는 것보다 Radar Chart로 각
> 대상의 특성을 비교하는 방법도 적합합니다. 표를 유지할까요, Radar
> Chart로 변경할까요?

또는:

> 이 데이터는 Radar Chart 외에도 항목별 Bar Chart로 표현할 수 있습니다.
> 종합적인 특성 비교가 목적이면 Radar Chart, 정확한 수치 비교가 목적이면
> Bar Chart가 적합합니다. 어떤 방향으로 구성할까요?

------------------------------------------------------------------------

## 14. Autonomy Boundary

AI에게 허용되는 자유:

-   Radar / Bar / Table 중 적절한 시각화 후보 제안
-   Chart 크기 및 위치 조정
-   Label 간격 조정
-   비교 대상 배치 순서 제안
-   데이터 특성에 따른 Chart 유형 추천

AI에게 허용되지 않는 자유:

-   평가점수 임의 생성
-   자사 우위를 위해 데이터 수정
-   서로 다른 단위를 근거 없이 동일 Scale로 변환
-   사용자가 제공한 수치 변경
-   실제 데이터가 없는 항목을 추정값으로 채우기

------------------------------------------------------------------------

## 15. Content Density Adaptation

비교 대상이 증가할 경우:

### 2개 대상

-   Radar Chart 2개 병렬
-   또는 하나의 Radar에 2개 Polygon Overlay 가능

### 3개 대상

-   원본과 같은 3-Column Multi-Radar를 우선

### 4개 대상

-   2×2 Radar Grid 검토

### 5개 이상

-   Radar Chart를 지나치게 축소하지 않는다.
-   Bar Chart / Comparison Table / 별도 슬라이드 분할을 우선 검토한다.

한 Radar Chart에 너무 많은 Polygon을 겹쳐 가독성을 떨어뜨리지 않는다.

------------------------------------------------------------------------

## 16. Overlay Radar Rule

하나의 Radar Chart에 여러 대상을 겹치는 방식은 제한적으로 사용할 수
있다.

권장: - 최대 2\~3개 대상

사용 조건: - 직접적인 Shape 비교가 중요한 경우 - Fill Transparency로 각
영역을 구분할 수 있는 경우 - Polygon 겹침으로 데이터 해석이 방해되지
않는 경우

3개를 초과하면 개별 Radar Chart 또는 다른 Chart를 우선한다.

------------------------------------------------------------------------

## 17. Avoid

-   근거 없는 점수 생성
-   Chart마다 다른 Scale 사용
-   Chart마다 축 순서 변경
-   8개를 초과하는 복잡한 축
-   지나치게 많은 Polygon Overlay
-   Chart별 크기 불일치
-   과도한 Grid 강조
-   3D Radar Chart
-   Shadow / Gradient 남용
-   장식 목적의 임의 색상 사용

------------------------------------------------------------------------

## 18. Soft Rule

동일한 평가기준을 사용하여 여러 기술·제품·기업의 종합적인 특성을 비교할
경우 Radar Chart를 우선적인 시각화 후보로 검토한다.

단, 정확한 수치 비교가 핵심이라면 Bar Chart 또는 Table을 우선한다.

사용자가 Chart 형식을 지정하지 않았고 5개 이상의 공통 비교항목이 제공된
경우, 시각화 변경이 전달력을 유의미하게 개선할 수 있다면 Radar Chart
또는 다른 적합한 Chart로 변환할지 사용자에게 제안할 수 있다.

------------------------------------------------------------------------

## 19. Layout Identity

이 레이아웃의 핵심 Identity:

`Key Advantages + Same-scale Multi-Radar + Consistent Axes + Bottom Target Labels`

가장 중요한 원칙:

1.  모든 Radar Chart의 축과 Scale이 동일할 것
2.  실제 제공된 데이터만 사용할 것
3.  5\~7개의 다차원 비교에서 우선 검토할 것
4.  정확한 수치 비교가 중요하면 다른 Chart를 선택할 것
5.  사용자가 형식을 지정하지 않은 경우 더 적합한 시각화가 있다면 변경
    여부를 질문할 수 있을 것
