# Process + Comparison Layout Reference

## 1. Purpose

공정·기술·소재의 **단계별 흐름(Process / Flow)** 을 먼저 보여주고, 그
흐름에서 발생하는 **기존 한계, 문제점, 개선 방향, 기존 기술 대비 신규
기술의 차이**를 같은 슬라이드 하단에서 연결하여 설명할 때 사용하는
레이아웃이다.

Reference의 핵심 시각 구조를 최대한 유지하되, 특정
제품명·공정명·이미지·문구 자체는 복제하지 않는다.

### Use When

-   공정 흐름을 설명한 뒤 해당 공정의 문제점 또는 개선 방향을 제시할 때
-   기존 기술과 신규 기술을 공정 맥락과 함께 비교할 때
-   소재/공정의 현재 한계와 개선 필요성을 한 장에서 설명할 때
-   Before → After 또는 Existing → Improved 관계를 공정과 함께 보여줄 때
-   여러 단계의 공정이 하단의 핵심 Insight/Comparison과 직접 연결될 때

### Do Not Use When

-   단순 공정 순서만 보여주면 충분한 경우
-   공정 없이 두 대상의 직접 비교만 필요한 경우
-   시간축 중심의 연혁/로드맵인 경우
-   3개 이상의 독립적인 메시지를 병렬 비교하는 것이 핵심인 경우

------------------------------------------------------------------------

## 2. Overall Composition

일반 콘텐츠 슬라이드의 공통 Header 영역은 Hard Rule을 그대로 적용한다.

Header 아래 본문 영역은 기본적으로 다음의 **2단 수직 구조**를 사용한다.

1.  **Upper Process / Flow Area**
2.  **Lower Comparison / Insight Area**

본문 가용 영역 기준 권장 비율: - Upper Process / Flow Area: 약
**55~60%**\ -\ Lower\ Comparison\ /\ Insight\ Area:\ 약\ **40~45%**

두 영역 사이에는 충분한 구분감을 주되 과도한 공백은 만들지 않는다. 전체
슬라이드는 위에서 아래로 자연스럽게 읽히는 하나의 스토리로 구성한다.

------------------------------------------------------------------------

## 3. Upper Process / Flow Area

### 3.1 Basic Structure

상단은 좌→우 방향의 Process Flow를 기본으로 한다.

`Stage 1 → Stage 2 → Stage 3 → Stage 4 → ...`

-   단계는 가능한 한 한 줄의 수평 흐름으로 구성한다.
-   각 단계의 중심축과 시각적 높이를 정렬한다.
-   단계 사이에는 명확한 Arrow 또는 Direction Indicator를 사용한다.
-   Arrow의 크기·두께·스타일은 전체 Process에서 동일하게 유지한다.
-   단계 수에 따라 각 요소의 크기와 간격을 균등하게 조정한다.
-   단계가 많더라도 요소를 지나치게 작게 축소하지 않는다.

### 3.2 Stage Composition

각 Process Stage는 필요한 항목으로 구성한다.

1.  Main Visual
2.  Stage Name
3.  Short Supporting Label
4.  Optional Phase Label

Main Visual을 가장 큰 시각 요소로 사용하고, Stage Name은 Visual과
명확하게 연결되도록 배치한다.

-   각 Stage는 Main Visual + Stage Name/설명을 하나의 시각적 단위로
    구성하고, Stage 사이는 Arrow로 연결해 전체가 하나의 Flow로
    읽히도록 한다.

### 3.3 Visual Asset

Process 단계가 실제 물질, 제품, 장비, 공장, 원료 등 **실체가 있는
대상**을 의미할 경우, 단순 아이콘보다 실제 제품·소재·공정·설비 Image
또는 Diagram을 우선 사용한다.

우선순위:

1.  사용자가 제공한 관련 이미지 — 존재하면 반드시 우선 활용한다.
2.  Reference/사내 자료에서 사용 가능한 적합한 이미지
3.  콘텐츠에 적합한 실제 사진(제품·소재·공정·설비)
4.  적절한 실제 이미지가 없는 경우에만 Diagram → Illustration → Icon
    순으로 대체한다.

Reference의 특정 사진 자체를 필수 요소로 간주하지 않는다. 이미지가 없는
경우 빈 Placeholder를 남기지 말고 콘텐츠의 의미에 적합한 다른 시각화
방식으로 대체한다.

### 3.4 Visual Scale

-   Main Visual은 Process 영역에서 충분히 크게 사용한다.
-   Visual은 장식적인 작은 아이콘처럼 배치하지 않고, 각 Process Stage의
    핵심 시각 요소로서 충분한 크기를 확보한다.
-   서로 다른 이미지 유형을 사용하더라도 시각적 크기와 무게를 균형 있게
    맞춘다.
-   제품/소재 이미지는 가능하면 배경이 정리된 형태를 사용한다.
-   불필요한 카드 테두리로 각 Stage를 감싸지 않는다.
-   Process Flow는 가용 폭과 높이를 적극 활용해 상단 영역이 지나치게
    비어 보이지 않도록 한다.
-   Diagram/Illustration/Icon으로 대체하는 경우에도 이를 이유로
    불필요한 여백을 크게 만들지 않는다 — Visual 크기와 밀도는 실제
    이미지를 사용할 때와 동일한 기준을 유지한다.

### 3.5 Generation / Version Badge (Optional)

콘텐츠에 실제 세대·버전 정보(예: 1세대/2세대, v1/v1.5 등)가 있는 경우에만
Process 영역 상단 또는 첫 Stage 인근에 작은 배지(Badge) 형태로 표시할 수
있다.

-   Phase Label(§4)과는 다른 요소다 — Phase Label은 하나의 Process를
    여러 구간으로 나누는 라벨이고, Generation Badge는 Process 전체가
    몇 세대·버전에 해당하는지 태깅하는 라벨이다.
-   세대·버전 정보가 없는 콘텐츠에 임의로 만들어 붙이지 않는다.
-   Process 흐름 자체보다 낮은 정보 위계를 가지며, 시각적으로
    과도하게 강조되지 않도록 한다.
-   상단과 하단이 서로 다른 세대·버전을 비교하는 슬라이드(예: 기존
    공정 vs 신규 공정)에서 하단 Comparison과의 대응 관계를 명확히
    하는 용도로 사용할 수 있다.

------------------------------------------------------------------------

## 4. Phase / Group Label

Process가 2개 이상의 큰 단계군으로 나뉘는 경우 Process 상단 또는 하단에
Phase Label을 사용할 수 있다.

예: `PRE-PROCESS | POST-PROCESS`, `INPUT | PROCESS | OUTPUT`

-   Phase Label은 Process 자체보다 낮은 정보 위계를 갖는다.
-   얇은 Line, Bracket 또는 구간 표시를 활용할 수 있다. 상위 Process
    Group 간 경계를 표시할 때는 Vertical Dashed Divider를 기본으로
    사용한다.
-   Phase 구분은 실제 콘텐츠에 의미가 있을 때만 사용한다.
-   단순 장식 목적으로 Phase를 임의 생성하지 않는다.
-   전처리/후처리 등 상위 Process Group이 실제로 존재하는 경우, 각
    Group마다 Label을 표시한다.
-   Vertical Dashed Divider는 화면 중앙에 고정하지 않고, 실제 Stage
    구성상 Group이 나뉘는 위치에 배치한다.
-   Divider는 개별 Stage 사이의 구분이 아니라 상위 Process Group 간
    경계를 표현하는 용도로만 사용한다.

------------------------------------------------------------------------

## 5. Lower Comparison / Insight Area

하단은 상단 Process에서 도출되는 핵심 문제, 비교 또는 개선 메시지를
설명한다.

콘텐츠에 따라 다음 구조 중 가장 적합한 것을 선택할 수 있다. - **Problem
vs Solution** - **Existing vs Improved** - **Before vs After** -
**Limitation vs Direction** - **Current Technology vs New Technology** -
**Limitation A + Limitation B → Improvement Need**

하단은 상단과 분리된 별개의 카드처럼 보이기보다 **상단 Process의 결론
또는 핵심 Insight**로 읽혀야 한다.

------------------------------------------------------------------------

## 6. Comparison Structure

### 6.1 Two-Side Comparison

두 대상을 직접 비교하는 경우 기본적으로 좌/우 2개 영역으로 구성한다.

`Existing / Problem | Improved / Solution`

-   좌우 영역의 폭과 정보량을 균형 있게 구성한다.
-   단, 정보량의 균형은 좌우 텍스트 분량이 동일해야 함을 의미하지
    않는다. 콘텐츠 특성상 한쪽에 더 많은 설명이 필요한 경우 비대칭
    구성을 허용한다.
-   비교 대상의 제목 위치와 정보 위계를 통일한다.
-   동일한 비교 기준이 있는 경우 시각적으로 같은 위치에 배치한다.
-   구조식, 그래프, 수치, 이미지 등 비교에 적합한 Visual을 적극
    활용한다.

### 6.2 Multiple Limitations to One Direction

2개 이상의 문제점이 하나의 개선 방향으로 수렴하는 경우:

`Limitation A | Limitation B → Improvement / Need`

-   문제점은 독립적으로 이해될 수 있도록 구분한다.
-   최종 개선 방향은 Arrow, Accent Label 또는 Callout을 사용해 연결한다.
-   개선 방향이 슬라이드의 핵심 결론으로 인식되도록 한다.

------------------------------------------------------------------------

## 7. Key Message Hierarchy

하단 각 영역의 핵심 메시지는 짧고 강하게 표현한다.

권장 위계:

**Category / Comparison Label → Key Message → Supporting Visual /
Evidence → Short Explanation**

-   긴 문단보다 핵심 문장과 시각자료 중심으로 구성한다.
-   중요 수치나 핵심 단어는 Design System의 강조 방식을 따른다.
-   같은 레벨의 메시지는 동일한 타이포그래피 위계를 유지한다.
-   좌우 비교에서 도출되는 결론이 하나로 수렴하는 경우, 각 영역에
    개별 Key Message를 반복하는 대신 좌우 영역을 가로지르는 **하나의
    공통 Key Message**를 사용할 수 있다. 이 경우 공통 Key Message는
    두 비교 영역의 Label과 Supporting Visual/Evidence 사이에 위치해
    상단 위계(Category/Comparison Label)와 하단 근거(Visual/Evidence)
    사이를 자연스럽게 잇는다.

------------------------------------------------------------------------

## 8. Connection Between Upper and Lower Areas

이 레이아웃의 핵심은 **Process와 Comparison을 한 슬라이드 안에서
연결하는 것**이다.

-   상단 Process가 단순 장식처럼 분리되어 보이지 않도록 한다.
-   하단의 문제점/비교 내용이 상단 어느 단계 또는 전체 Process와
    관련되는지 이해 가능해야 한다.
-   필요할 경우 Connector, Arrow, Alignment, Shared Color Cue 등을
    사용하여 관계를 표현한다.
-   하단 Comparison/Insight가 Process 전체가 아니라 **특정 단계**에서
    직접 파생되는 경우, 해당 Process 단계를 Callout/Highlight(강조
    표시, 밑줄, 색상 강조 등)로 표시해 상단과 하단의 대응 관계를 즉시
    알아볼 수 있게 할 수 있다.
-   Process Callout은 관련된 하나의 Stage에만 사용하고, 여러 Stage에
    남용하지 않는다.
-   연결선은 최소한으로 사용하고 복잡한 배선 형태를 피한다.
-   시선 흐름은 기본적으로 `상단 좌→우 → 하단` 순서를 유지한다.

------------------------------------------------------------------------

## 9. Density & Spacing

Reference와 유사한 **중간\~높은 수준의 정보 밀도**를 기본으로 한다.

-   Process Visual을 지나치게 작게 만들고 여백을 크게 남기지 않는다.
-   하단 Comparison 영역도 충분한 높이를 확보한다.
-   콘텐츠가 충분한 경우 슬라이드 중앙과 하단에 불필요한 빈 공간을
    남기지 않는다.
-   단, 요소를 억지로 확대하여 답답하게 만들지 않는다.
-   Process와 Comparison 사이의 간격은 명확한 영역 구분이 가능하되
    흐름이 끊기지 않는 수준으로 유지한다.
-   좌우 여백과 요소 간 간격은 전체 Deck의 Hard Rule 및 Design System과
    조화를 유지한다.

------------------------------------------------------------------------

## 10. Alignment

-   상단 Process는 본문 가용 폭을 적극적으로 사용한다.
-   첫 Stage와 마지막 Stage가 본문 좌우 경계에 지나치게 붙지 않도록
    한다.
-   Stage Visual의 중심축을 최대한 정렬한다.
-   하단 Comparison의 좌우 시작점은 상단 Process 영역과 시각적으로
    연결되도록 한다.
-   반복되는 제목, Label, Visual의 기준선을 맞춘다.
-   불필요한 비대칭은 피하되 콘텐츠 의미상 필요한 비대칭은 허용한다.

------------------------------------------------------------------------

## 11. Visual Style

색상, 폰트, 선, Arrow, 이미지 처리, 차트, 강조 방식은 **Claude PPT
Design System**을 따른다.

Layout Reference 자체에서 새로운 브랜드 스타일을 만들지 않는다.

단, Reference의 다음 시각적 특성은 구조적 특징으로 유지한다. - 상단에
크고 명확한 Process Visual - 좌→우의 강한 흐름 - 하단에 명확히 구분된
Insight / Comparison 영역 - 시각자료 중심의 설명 - 과도한 Card UI보다
열린 Presentation Layout 우선 - 한 장에서
`Flow → Issue/Comparison → Conclusion`이 읽히는 구조

------------------------------------------------------------------------

## 12. Flexibility

### Must Preserve

-   Upper Process / Flow + Lower Comparison / Insight의 2단 구조
-   상단 좌→우 Process 흐름
-   하단의 비교/문제/개선 정보 구조
-   상단과 하단 사이의 논리적 연결
-   충분한 Main Visual 크기와 정보 밀도

### May Adapt

-   Process 단계 수
-   각 단계의 이미지/아이콘/도식 유형
-   Phase Label 사용 여부
-   하단의 비교 유형
-   하단 영역의 2분할/다중 문제→결론 구조
-   콘텐츠 양에 따른 세부 영역 비율

------------------------------------------------------------------------

## 13. Avoid

-   Process를 작은 아이콘만 나열한 단순 Navigation처럼 표현
-   상단과 하단이 서로 관련 없는 두 슬라이드를 붙인 것처럼 보이는 구성
-   이미지가 없다는 이유로 빈 공간을 크게 남기는 것
-   모든 Stage를 개별 Card로 감싸 시각적으로 답답하게 만드는 것
-   Process Arrow 스타일이 단계마다 달라지는 것
-   하단에 긴 설명 문단만 배치하는 것
-   Reference의 특정 이미지·제품명·문구를 그대로 복제하는 것
-   Layout을 맞추기 위해 콘텐츠 의미를 왜곡하는 것
-   Hard Rule 또는 Design System을 Layout Reference가 덮어쓰는 것

------------------------------------------------------------------------

## 14. Rule Priority

적용 우선순위:

1.  **Hard Rule** --- CI, Sub Message, Divider, Section Label, Main
    Title, Page Number 및 기타 공통 고정 요소
2.  **Claude PPT Design System** --- Color, Typography, Chart Style,
    Image Style, Visual Language
3.  **Process + Comparison Layout Reference** --- Upper Process / Flow
    구조, Lower Comparison / Insight 구조, 영역 비율과 정보 흐름, 두
    영역의 연결 방식

본 Layout Reference는 Hard Rule 및 Claude PPT Design System을 변경하거나
대체하지 않는다.

------------------------------------------------------------------------

## 15. Selection Rule

슬라이드 콘텐츠에 다음 두 조건이 **동시에 존재할 때** 이 Layout을 우선
고려한다.

1.  단계별 공정·기술·소재 흐름을 시각적으로 설명할 필요가 있음
2.  해당 흐름과 직접 연결되는 문제점, 한계, 기존/개선 비교 또는 핵심
    Insight를 같은 슬라이드에서 전달할 필요가 있음

공정 흐름만 필요한 경우에는 일반 Process Layout을 우선 사용한다. 비교만
필요한 경우에는 Comparison Layout을 우선 사용한다.

단순히 공정 단계와 비교 정보가 모두 존재한다는 이유만으로 강제 적용하지
않고, **두 정보가 하나의 스토리로 연결될 때** 적용한다.
