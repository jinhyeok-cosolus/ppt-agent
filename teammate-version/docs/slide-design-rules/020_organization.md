# Organization Chart --- Curved Leadership

> 임원 프로필과 조직 구성을 하나의 곡선 다이어그램으로 통합하는 조직도
> 레이아웃. 단순 계층 표현보다 핵심 리더를 중심으로 조직이 확장되는
> 구조와 각 책임자의 전문성을 함께 전달할 때 사용한다.

------------------------------------------------------------------------

## 1. Layout Intent

이 레이아웃의 핵심은 CEO를 중심으로 주요 임원·조직이 좌우로 펼쳐지는
곡선형 구조이다.

전통적인 피라미드형 조직도보다 다음 내용을 강조하는 경우 우선적으로
사용한다.

-   핵심 경영진 및 주요 책임자
-   각 책임자의 전문 분야
-   담당 조직 및 팀
-   조직 간 관계
-   전문 인력 중심의 기업 역량

곡선은 단순 장식이 아니라 조직 전체를 하나의 시각적 흐름으로 연결하는
핵심 디자인 요소로 사용한다.

------------------------------------------------------------------------

## 2. Core Composition

기본 구조는 다음과 같다.

``` text
                         [CEO Portrait]
                         CEO / Name
                      Profile / Career

    Team A ●                                  ● Team B
             ╲                              ╱
              ╲____________________________╱
                         ●
                   Core Organization

     [Executive]        [Executive]        [Executive]
       Profile            Profile            Profile
```

-   CEO 또는 최고 책임자를 상단 중앙에 배치한다.
-   주요 임원은 좌·중·우 영역으로 분산 배치한다.
-   주요 조직은 CEO를 중심으로 하나의 완만한 곡선으로 연결한다.
-   전체 인상은 피라미드보다는 부채꼴 형태로 확산되도록 구성한다.

------------------------------------------------------------------------

## 3. Curved Organization Line

곡선형 연결을 기본값으로 사용한다.

### 기본 형태

-   좌측 조직 → 중앙 → 우측 조직을 하나의 연속된 Arc로 연결한다.
-   여러 개의 짧은 곡선을 조합하기보다 하나의 긴 곡선을 우선한다.
-   곡률은 완만하게 유지한다.
-   CEO 하단을 지나도록 구성하되 CEO Portrait에 직접 연결하지 않아도
    된다.
-   곡선의 양 끝 또는 주요 조직 위치에는 Solid Circular Node를 사용할 수
    있다.
-   화살표는 사용하지 않는다.
-   곡선은 위계선을 직접적으로 표현하기보다
    `핵심 리더를 중심으로 조직이 펼쳐지는 관계`를 표현하는 시각적 장치로
    사용한다.

------------------------------------------------------------------------

## 4. Straight Line Exception

직선은 기본 디자인이 아니라 예외 처리로 사용한다.

다음 상황에서는 부분적으로 직선을 허용한다.

-   텍스트 또는 Portrait로 인해 곡선이 지나갈 물리적 공간이 부족한 경우
-   두 Node 사이의 거리가 매우 짧아 곡률 표현이 의미 없는 경우
-   곡선 사용 시 Portrait, 본문 또는 다른 Connector와 충돌하는 경우
-   동일한 수평 또는 수직 관계를 직선으로 표현하는 것이 더 자연스러운
    경우

가능한 경우 전체 조직도의 핵심 연결 구조는 곡선으로 유지한다.

곡선을 유지하기 위해 본문 크기를 과도하게 축소하지 않는다.

------------------------------------------------------------------------

## 5. Node System

조직의 성격에 따라 Node 표현 방식을 구분한다.

  Node Type                    Visual Treatment
  ---------------------------- -----------------------
  CEO / Executive              원형 Portrait
  Team / Department            Solid Dot + Team Name
  Research Center / Division   Text Label
  Sub-team                     Dot Bullet + Text

동일한 Level의 Node는 동일한 시각적 Weight를 유지한다.

------------------------------------------------------------------------

## 6. Portrait System

임원 또는 주요 책임자는 원형 Portrait를 기본으로 사용한다.

### 기본 원칙

-   동일한 원형 Mask 사용
-   동일하거나 유사한 배경 톤 적용
-   가능하면 인물 사진의 채도 및 명암 수준 통일
-   동일 Level 인물은 동일 크기 유지

### Visual Priority

CEO \> 주요 임원 \> 팀 책임자

CEO는 조직도의 시각적 Anchor 역할을 하므로 가장 높은 Priority를
부여한다.

단, 배치 공간 확보를 위해 동일 Level 인물의 크기를 임의로 크게 차등
적용하지 않는다.

### 사진 미확보 시 Placeholder

실제 인물 사진이 아직 제공되지 않은 경우, 가짜 사진을 임의로 생성하거나
이니셜 아바타로 대체하지 않는다.

-   점선(Dashed) 테두리의 원형 Placeholder를 사용한다.
-   내부에는 간단한 인물 실루엣 아이콘만 배치한다(이니셜 텍스트는 실제
    사진처럼 오인될 수 있어 사용하지 않는다).
-   배경은 Neutral/Mist 계열 톤을 사용한다.
-   실제 사진이 제공되면 Placeholder를 그대로 대체하되, 원형 Mask·크기
    규칙(동일 Level 동일 크기)은 유지한다.

------------------------------------------------------------------------

## 7. Executive Information Structure

인물 정보는 다음 순서를 기본으로 한다.

1.  Position
2.  Name
3.  Expertise / Main Role
4.  Career
5.  Assigned Team

예시:

``` text
CTO
홍길동

유기합성

▪ 2021.08  ○○대학교 화학 박사
▪ 2022.03~ ○○기업 연구소장
▪ 논문 18편 / 특허 7편

● 개발1팀 (6명)
● 개발2팀 (4명)
```

모든 정보를 반드시 사용할 필요는 없다.

콘텐츠 중요도에 따라 Career 또는 Team Information을 축약할 수 있다.

------------------------------------------------------------------------

## 8. Information Hierarchy

권장 시각적 우선순위:

1.  Portrait
2.  Position
3.  Name
4.  Team / Organization Name
5.  Expertise
6.  Career
7.  Sub-team Information

팀명 및 조직명은 Connector와 연계하여 관계가 즉시 인식되도록 배치한다.

경력 정보는 조직도 자체보다 높은 시각적 Weight를 갖지 않도록 한다.

------------------------------------------------------------------------

## 9. Team Label

Team Node는 다음 구조를 기본으로 한다.

`● 팀명 (N명)`

-   Solid Dot + Team Name 조합 사용
-   인원 정보가 제공된 경우 괄호로 병기 가능
-   팀명은 한 줄 표현을 우선한다.
-   지나치게 긴 팀명은 의미를 훼손하지 않는 범위에서 축약 가능

Sub-team은 담당 임원 정보 하단에 Bullet List 형태로 배치할 수 있다.

### 배치 위치

-   팀/조직명 라벨은 곡선 위 해당 Node 지점(위쪽)에 배치하는 것을
    기본으로 하며, 인물의 Portrait·Position·Name 정보 블록(아래쪽)과
    시각적으로 분리한다.
-   이렇게 분리하면 "이 Node가 어떤 조직인가"와 "이 조직을 누가
    이끄는가"가 한눈에 구분된다.
-   Node 라벨과 인물 정보 블록을 하나로 합쳐 인물 블록 안에 조직명을
    반복 표기하지 않는다(단, 인물 정보의 Assigned Team 항목에 인원수를
    함께 표기하는 것은 허용한다).

------------------------------------------------------------------------

## 10. Placement Logic

### CEO

-   상단 중앙 배치
-   전체 조직도의 Visual Anchor 역할

### Other Executives

-   좌측 / 중앙 하단 / 우측 영역으로 분산
-   화면 전체에 균형 있게 배치
-   완전한 좌우 대칭보다 콘텐츠 밀도에 따른 시각적 균형을 우선

### Text Alignment

-   좌측 인물: Left Align 우선
-   중앙 인물: Center 또는 Left Align 선택 가능
-   우측 인물: 화면 바깥으로 텍스트가 밀리지 않는 방향으로 정렬

정렬 방식 자체보다 Portrait와 정보 블록 간 관계의 명확성을 우선한다.

------------------------------------------------------------------------

## 11. Content Density Adaptation

정보량 증가 시 다음 순서로 대응한다.

1.  중요도가 낮은 Career 정보 축약
2.  세부 Team 정보 축약
3.  Portrait 및 Node 간 간격 조정
4.  Portrait 크기 소폭 조정
5.  단일 Arc 내 Node 재배치
6.  충분한 가독성이 확보되는 경우 2단 Arc 구조 검토
7.  곡선형 구조로 가독성 확보가 불가능한 경우 다른 조직도 레이아웃 검토

글자 크기를 과도하게 축소하여 레이아웃을 억지로 유지하지 않는다.

------------------------------------------------------------------------

## 12. Multi-Arc Expansion

기본형은 Single Arc 구조이다.

조직 또는 인물 수가 증가할 경우 필요에 따라 두 번째 Arc를 추가할 수
있다.

``` text
                   CEO
                    │

       ●──────── Curved Arc ────────●
             Major Organizations

          ●──── Second Arc ────●
               Sub Organizations
```

단, Arc 추가는 자동적으로 적용하지 않는다.

다음 조건을 만족할 때만 사용한다.

-   조직 간 관계가 명확히 2개 Level로 구분되는 경우
-   두 번째 Arc를 사용해도 충분한 여백이 확보되는 경우
-   Connector가 서로 교차하지 않는 경우
-   정보 가독성이 Single Arc보다 실제로 개선되는 경우

------------------------------------------------------------------------

## 13. Visual Simplicity

곡선 조직도 자체가 강한 Visual Element이므로 추가적인 장식을 최소화한다.

Avoid:

-   과도한 Box 사용
-   조직별 배경 Panel 남용
-   Connector Arrow
-   복잡한 S-Curve
-   Connector 교차
-   불필요한 Shadow
-   Gradient Connector
-   지나치게 많은 색상
-   조직별 임의 색상 구분

Portrait + Curve + Node + Typography만으로 조직 관계를 전달하는 것을
우선한다.

------------------------------------------------------------------------

## 14. Soft Rule

조직 관계가 비교적 단순하고 핵심 임원의 전문성과 담당 조직을 함께
보여주는 경우 Curved Organization Layout을 우선적인 시각화 후보로
검토한다.

곡선의 정확한 좌표, Portrait 위치 및 각 정보 블록의 크기는 콘텐츠 분량에
따라 조정할 수 있다.

완전한 대칭보다 시각적 균형과 정보 가독성을 우선한다.

콘텐츠가 증가하더라도 곡선형 레이아웃의 핵심 특징인 다음 요소는 최대한
유지한다.

-   중앙 핵심 리더
-   좌우로 확산되는 조직 구조
-   완만한 Arc
-   Solid Node
-   원형 Portrait
-   최소화된 Connector

------------------------------------------------------------------------

## 15. Layout Identity

이 레이아웃의 핵심 디자인 Identity는 다음과 같다.

`Central Leader + Circular Portrait + Single Arc + Solid Nodes + Distributed Leadership`

레이아웃을 변형하더라도 위 조합이 유지되어 원본 디자인의 시각적 정체성이
사라지지 않도록 한다.

곡선은 기본 디자인 언어이며, 직선은 콘텐츠 또는 공간 제약을 해결하기
위한 보조 수단으로만 사용한다.
